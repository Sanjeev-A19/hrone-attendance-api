# REVIEW.md

Problems I found in the starter `app/main.py`, in the order they appear in the file. I fixed all of them.

| # | Where | What was wrong | How I would notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | The client was not timezone-aware, so every datetime came back naive and the code had to guess the zone. There was also no timeout, so a dead database would hang requests. | A stored punch-in comes back with no tzinfo, and converting it to epoch ms shifts by the server's UTC offset. | `tz_aware=True` (always UTC) plus a server selection timeout. |
| 2 | startup | No indexes at all. `(emp_code, date)` was not unique, so nothing stopped duplicate records, and every list or analytics query scanned the whole collection. | Two parallel punch-ins both succeed. `/attendance` gets slow around 100k rows. | `ensure_indexes()` runs at startup and is safe to repeat. It has unique indexes on `emp_code` and on `(emp_code, date)`. |
| 3 | `compute_late_minutes` | It builds the shift start from the punch-in's UTC date, so the shift is read in UTC instead of IST. It also flooring-then-compares (`minutes > 10`), so 09:40:01 gives 0 instead of 10. Seconds are not truncated and overnight shifts are ignored. | Shift 09:30, punch-in 09:40:01 IST returns 0. | The shift start is built in IST from the attendance date. Late means more than 600 seconds, then `seconds // 60`. |
| 4 | `compute_work_hours` | Python `round()` on a float rounds half to even, but the rule says half-up. | 18 seconds of work should give 0.01 and gave 0.0. | `Decimal(seconds) / 3600` with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum. The shift end is always placed on the punch-in date, which breaks overnight shifts. | Shift ends 18:30, punch-out 18:40: it returns 10 where 0 is right. An overnight 22:00-06:00 shift gives a negative number that is clipped to 0. | The shift end is built in IST on the correct day (plus one day for overnight). Overtime counts only when it is at least 30. |
| 6 | `GET /health` | Always returns 200, even when MongoDB is down. | Stop MongoDB and call `/health`. | It pings MongoDB and returns 503 on failure. It also retries index creation. |
| 7 | `POST /employees` | Check-then-insert race. Two parallel creates can both pass the `find_one`. | Send 10 identical creates at once. | A unique index on `emp_code`. A `DuplicateKeyError` becomes 409. |
| 8 | `POST /employees` | No validation of `emp_code` format, e-mail, `HH:MM` shifts, equal shift times or `joined_on`. `created_at` was local naive time and went out as a datetime, not epoch ms. | `joined_on: "2026-02-30"` is accepted. | Pydantic patterns, a real date check, a validator for equal shifts, and UTC `created_at` returned as epoch ms. |
| 9 | `GET /employees` | `skip = page * page_size` skips the whole first page. `total` counted the entire collection and ignored the filter. No sort, no limits on `page` or `page_size`. | `page=1` returns the second page. With a department filter, `total` is still the global count. | `skip = (page - 1) * page_size`, `count_documents(filter)`, sort by `emp_code`, and bounds on both parameters. |
| 10 | `POST /attendance/punch-in` | For an unknown employee `emp` is `None`, so `emp["shift_start"]` raises a `TypeError` and the user gets a 500 instead of a 404. | Punch in with an `emp_code` that does not exist. | `find_employee` raises 404. |
| 11 | `POST /attendance/punch-in` | `datetime.fromtimestamp(ms / 1000)` uses the server's local time and returns a naive value. The date comes from that instead of IST, and the overnight rule is missing. `if body.punched_at` treats 0 as missing. Seconds are not truncated, and second-style or float timestamps are accepted. | Run the server in UTC and punch in at 00:30 IST: the record gets the previous day's date. | `ms_to_dt` gives UTC-aware, second-truncated values. `attendance_date` follows R1 including overnight shifts. A strict `EpochMs` type rejects seconds, floats and strings with 422. |
| 12 | `POST /attendance/punch-in` | Another check-then-insert race (`find_one` then `insert_one`). | Two parallel punch-ins both return 201. | Insert directly and let the unique `(emp_code, date)` index decide. `DuplicateKeyError` becomes 409. |
| 13 | `POST /attendance/punch-in` | `status` accepts any string, including `ABSENT` and nonsense. The response adds an `id` (the ObjectId) that is not in the contract and returns raw datetimes. | `status: "ABSENT"` returns 201. | The status is limited to `PRESENT`, `WFH`, `ON_DUTY`. `record_out` builds the exact contract shape with epoch ms. |
| 14 | `GET /attendance` | It loads the whole collection into memory, then sorts and pages in Python. There is no `emp_code` tie-break in the sort, and `total` comes from the loaded list. | At 100k rows it is slow and uses a lot of memory. Rows with the same date come back in unstable order. | Sorting, skip and limit now happen in MongoDB (`date` descending, then `emp_code`), backed by compound indexes. `count_documents` gives the total. |
| 15 | `GET /attendance` | No validation of dates, of `date_from > date_to` (should be 422), of status or of `page_size`. It returns `_id` as `id`, datetimes instead of epoch ms, and ignores that legacy rows can lack fields. | `date_from=banana` gives an empty result instead of 422. A legacy row without `half_day` is returned without it. | Validated query types, a 422 for a reversed range, and `record_out` fills defaults for `late_minutes`, `overtime_minutes`, `half_day` and `history`. |
| 16 | whole file | Database errors turn into bare 500s. | Stop MongoDB and call any endpoint. | A `PyMongoError` handler returns 503. |

## Things I looked at and left alone

* `load_dotenv()` without `override=True`: variables already set in the environment win over the `.env` file, which is what the contract asks for.
* Plain `def` endpoints with the synchronous PyMongo client: FastAPI runs them in a thread pool and `MongoClient` is thread-safe. Correctness under concurrency comes from the unique indexes and conditional updates, not from the client.
* The defaults in `EmployeeIn` (09:30 and 18:30) match the contract.
