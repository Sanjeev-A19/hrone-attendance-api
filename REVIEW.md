# REVIEW.md

Defects found in the starter `app/main.py`, in file order. All are fixed in the submitted file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Client is not `tz_aware`, so every datetime read back is naive. Naive values are then treated as local time elsewhere. No timeouts either. | `punch_in` read back has no tzinfo; epoch conversion shifts by the server's UTC offset. | `tz_aware=True` (always UTC-aware) and `serverSelectionTimeoutMS`. |
| 2 | startup | No indexes at all. `(emp_code, date)` was never unique, so nothing stops duplicate records. Every list/analytics query is a collection scan. | Two parallel punch-ins both succeed; `/attendance` slows down at 100k rows. | `ensure_indexes()` at startup (idempotent, named indexes), unique `emp_code` and unique `(emp_code, date)`. |
| 3 | `compute_late_minutes` | Uses `punch_in.replace(hour=..)` on a UTC datetime, so shift start is read in UTC, not IST. Late is `minutes > 10` after flooring, so 09:40:01 gives 0 (should be 10). Seconds are not truncated. Overnight shifts are ignored. | Shift 09:30, punch-in 09:40:01 IST returns 0. | Shift start is built in IST from the attendance date. Late if `seconds > 600`, then `seconds // 60`. |
| 4 | `compute_work_hours` | Python `round()` is banker's rounding on a float. R4 needs half-up. | 18 seconds of work: expected 0.01, got 0.0. | `Decimal(seconds) / 3600` with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum. Shift end is on the punch-in's date, so overnight shifts are wrong. `date_str` is parsed naively. | Shift ends 18:30, punch-out 18:40: returns 10, should be 0. Overnight 22:00-06:00 gives a negative value clipped to 0. | Shift end is built in IST on the right day (+1 for overnight). Result counted only when >= 30. |
| 6 | `GET /health` | Always 200 even when MongoDB is down. | Stop MongoDB, call `/health`. | Pings MongoDB, 503 on failure. Also retries index creation. |
| 7 | `POST /employees` | Check-then-insert race: two parallel creates can both pass the `find_one`. | Fire 10 identical creates at once. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. |
| 8 | `POST /employees` | No validation: `emp_code` format, e-mail, `HH:MM` shifts, `shift_start == shift_end`, `joined_on` as a real date. Wrong `created_at` (local naive time), returned as a datetime/ISO string, not epoch ms. Extra fields leak back. | `joined_on: "2026-02-30"` is accepted. | Pydantic patterns, a real date check, a model validator, UTC `created_at` returned as epoch ms through `employee_out`. |
| 9 | `GET /employees` | `skip = page * page_size` skips the first page. `total` counts the whole collection, not the filter. No sort. No bounds on `page` / `page_size`. | `page=1` returns page 2. `department=X` still reports the global total. | `skip = (page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `Query(ge=1)` / `le=100`. |
| 10 | `POST /attendance/punch-in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError`, a 500. Should be 404. | Punch in with an unknown `emp_code`. | `find_employee` raises 404. |
| 11 | `POST /attendance/punch-in` | `datetime.fromtimestamp(ms / 1000)` uses server-local, naive time. The date comes from that, not from IST (R1). Overnight rule missing. `if body.punched_at` treats 0 as "missing". Not truncated to seconds. Seconds/float/string timestamps accepted. | Server in UTC: punch-in at 00:30 IST gets the previous day's date. | `ms_to_dt` (UTC-aware, truncated); `attendance_date` follows R1 including overnight; strict `EpochMs` type (422 for seconds, floats, strings). |
| 12 | `POST /attendance/punch-in` | Check-then-insert race (`find_one` then `insert_one`), so duplicates are possible. | Two parallel punch-ins: two 201s. | Insert directly; the unique `(emp_code, date)` index decides; `DuplicateKeyError` becomes 409. |
| 13 | `POST /attendance/punch-in` | `status` is any string, so `ABSENT` or `"banana"` is accepted. The response adds a non-contract `id` (the ObjectId) and returns raw datetimes. | `status: "ABSENT"` gets 201. | `Literal["PRESENT","WFH","ON_DUTY"]`; `record_out` builds the exact contract shape with epoch ms. |
| 14 | `GET /attendance` | Loads the whole collection into memory, sorts and pages in Python. Sort has no `emp_code` tie-break. `total` is computed from the loaded list. | 100k rows: slow and memory-heavy. Same-date rows come back in unstable order. | Sort, skip and limit in MongoDB with `date desc, emp_code asc`, backed by compound indexes. `count_documents` for the total. |
| 15 | `GET /attendance` | No validation: bad dates, `date_from > date_to` (must be 422), unknown status, huge `page_size`. Returns `_id` as `id`, datetimes not epoch ms, no defaults for legacy rows. | `date_from=banana` gives an empty result, not 422. A legacy record without `half_day` is returned without it. | Validated query types, 422 on reversed range, `record_out` fills defaults for missing `late_minutes`, `overtime_minutes`, `half_day`, `history`. |
| 16 | whole file | Endpoints raise nothing for database outages; a Mongo error is a bare 500. | Stop MongoDB, call any endpoint. | `PyMongoError` handler returns 503. |

## Looked at and left as is

* `load_dotenv()` without `override=True`: real environment variables already take priority, which is what the contract asks for.
* Plain `def` endpoints with the synchronous PyMongo client: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so concurrent requests are fine. Correctness under concurrency comes from the unique indexes and conditional updates, not from the client.
* The default values in `EmployeeIn` (`09:30` / `18:30`) match the contract.
